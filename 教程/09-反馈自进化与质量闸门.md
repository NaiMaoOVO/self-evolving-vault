# 09 反馈自进化与质量闸门

## 目标

让真实反馈改变下一轮，同时防止一次意见污染全局。

## 反馈提示词

```
记录我对【成果】的反馈，保留原话并拆为：- 正反馈/负反馈/缺口/结果数据；- 对象：事实、判断、方法、结构、表达、风险、格式；- 范围：本成果/同类任务/全局；- 强度：一次、重复、结果数据；- 动作：立即修事实错误、只记录、提出进化提案。除事实错误和安全问题外，一次反馈不得直接改全局画像。
```

## 周进化提示词

```
读取最近7天反馈、采用/否决成果、画像、方法、模板、Skill和待验证：1. 聚类信号；2. 至少重复2次或有结果数据才提出稳定规则；3. 每项写证据、旧规则、新规则、影响、风险、观察周期；4. 用户批准前不修改；5. 批准后只做增量，version+1；6. 用同类旧任务和新任务做前后对照；7. 没有行为差异不得标evolved；8. 无合格信号就写"本周无可验证进化"。
```

## 质量闸门

施工agent必须实现并测试以下检查：

- 资源层零覆盖。
- secret扫描。
- 来源存在、日期有效。
- 事实与判断分离。
- 不虚构实测、经历和引用。
- 不重复生产旧成果。
- 每轮唯一结案。
- 抓取失败不等于无新增。
- GBrain页面/索引/embedding一致性。
- 状态文件一致。
- 中间页不冒充成果。
- 用户目标质量高于技术通过。
- 连续低分或重复否决触发暂停扩量。
- 画像长期无更新触发审计，不强制伪升级。

## 验证提示词

```
选取一条真实重复反馈，执行完整进化：反馈证据→提案→用户批准→规则版本更新→同类任务前后对照。同时制造一个只有单次意见的反馈，确认系统不会直接升级全局规则。检查所有质量闸门能对已知坏样本报FAIL，对合格样本报PASS。
```
