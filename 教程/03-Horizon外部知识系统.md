# 03 Horizon外部知识系统

## 目标

让高质量外部资料进入资源层，同时保留原始证据、时间边界和失败事实。

## 施工提示词

```
请安装并配置Horizon。先读取官方README、中文README、配置指南、env示例、config示例和运行时声明。第一步｜职业信息源访谈询问：职业、责任、长期主题、近期主题、语言、地区、时效、噪声容忍度、付费源、禁止源。输出候选源表，先让用户确认。第二步｜最小安装- 核对Python最低版本和推荐依赖管理方式；- 说明安装路径和下载内容；- secret只进.env/环境变量，.env必须被版本控制忽略；- 从3—8个高质量源开始；- 优先官方RSS、专业机构、期刊/博客、明确关注的GitHub Release；- 需要额外token或存在合规风险的源默认关闭。第三步｜配置- AI provider、model、变量名；- 时间窗口、评分阈值、语言；- 原始数据与摘要输出目录；- 默认关闭邮件、Webhook、Pages和公开发布；- 所有URL、账号和私有源标记敏感等级。第四步｜Obsidian适配- 原始条目进入00_资源库/外部知识/；- 运行报告进入04_系统维护/运行记录/；- 每条保留唯一ID、标题、作者/机构、发布时间、原始URL、来源类型、抓取时间；- AI摘要与原文分字段保存；- 上游项目不支持时，先写适配器需求、设计、实现和测试；- 不直接修改上游核心代码；- 同一条目重复运行必须幂等。第五步｜小窗口试跑运行小时间窗，记录各源抓取数、失败数、去重数、入库数和输出路径。
```

## 验证提示词

```
独立验证Horizon：1. 抽查至少5条原始URL、作者、发布时间和抓取时间；2. 检查时间窗口边界；3. 同一窗口运行两次，重复新增必须为0；4. 人为使用一个无效测试源，必须报告"抓取失败"，不得写"无新增"；5. AI provider失败时，原始资料仍应保留；6. 原始资料与AI摘要不得混写；7. secret不得出现在vault、日志或Git；8. 未经授权的邮件、Webhook、公开发布必须为0；9. Horizon停用后，既有知识库仍能工作。按网络、权限、运行时、依赖、凭据、上游、解析、时间边界、去重、适配器分类问题。输出PASS/FAIL。
```

## 通过标准

- 真实来源可追溯。
- 重跑不重复。
- 部分源或AI失败不伪造成功。
