# 05 职业扩展包生成器

## 目标

用用户自己的职责、历史成果和反馈，生成可替换的职业包；不靠职业刻板印象。

## 职业包结构

```
04_系统维护/职业包/<职业名称>/
├── 职责与边界.md
├── 输入源地图.md
├── 成果类型与完成定义.md
├── 七张画像入口.md
├── 判断规则.md
├── 工作流路由.md
├── 质量标准.md
├── 风险与合规.md
├── 黄金样本.md
├── 反面样本.md
└── 反馈指标.md
```

## 生成提示词

```
请为我生成职业扩展包。禁止依据职业名称直接猜规则。阶段A｜访谈询问角色、职责、不负责事项、高频任务、输入、成果、服务对象、风险、评价指标和失败案例。阶段B｜证据采样读取用户明确授权的历史资料：- 至少10份代表性成果；不足时明确样本不足；- 至少3份用户认可成果；- 至少3份被修改、否决或失败的成果；- 项目复盘、评价数据和用户明确偏好。记录逐份是否全文读、关键证据和敏感等级。阶段C｜七张画像生成角色职责、目标成果、专业知识、工作方法、决策偏好、表达交付、风险边界。确定性规则需至少2条独立证据，或1次用户明确确认；否则放"待确认假设"。阶段D｜生产路由对每类输入定义：- 进入哪层；- 怎样蒸馏；- 生成哪种成果；- 完成定义；- 谁验收；- 哪类反馈进入进化。阶段E｜样本建立黄金样本、反面样本和两者差异；不得复制私人内容到公开模板。阶段F｜用户确认先展示证据表和候选规则，用户批准后才写入active职业包，version=1。
```

## 输出实例

```
规则：高风险决策必须列出证据日期和适用范围
证据：[[历史成果A]]、[[审阅反馈B]]
影响：决策备忘录模板
待验证：未来3次任务
```

## 验证提示词

```
审计职业包：1. 每条规则是否有证据；2. 是否混入职业刻板印象；3. 是否有黄金与反面样本；4. 是否覆盖输入→成果→反馈；5. 是否定义完成和失败；6. 是否存在私人信息泄露；7. 用一个旧任务回放，输出是否更接近用户认可样本。无真实历史资料时只能给"候选包"，不得标active。
```
