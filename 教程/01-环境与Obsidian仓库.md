# 01 环境与Obsidian仓库

## 目标

从官方渠道安装Obsidian，创建独立vault，并让agent只在授权目录施工。

## 施工提示词

```
你是安装工程师。请分四个检查点执行，任一失败就停止。检查点A｜只读体检- 识别操作系统、版本、CPU架构、磁盘空间和当前用户；- 检查Obsidian、Git和目标agent是否已安装，报告版本与真实路径；- 查找同名vault和未备份资料；- 只使用Obsidian官方帮助与下载页核对当前安装方式。检查点B｜安装Obsidian- 按操作系统从官方渠道安装；- 需要GUI或管理员权限时先请求授权；- 不安装社区插件、主题、Sync或Publish；- 报告来源、版本和安装位置。检查点C｜创建vault- 询问名称、绝对路径、是否放在云同步目录；- 同名目录存在时停止；- 用Obsidian创建vault；- 创建"安装验证.md"，记录vault名称、绝对路径和一条随机测试句；- 关闭并重开Obsidian，确认文件仍在。检查点D｜agent工作区- 让agent从文件系统只读打开同一文件；- 核对Obsidian和文件系统看到的是同一个inode/真实路径对象；- 建立AGENTS.md最小入口：只能写vault，删除、外发、批量改名先授权；- 不建立业务目录，留给后续章节。输出：环境体检、安装记录、vault记录和权限边界。不得显示secret。
```

## 预期结果

```
Obsidian：官方来源，已启动
Vault：/绝对路径/知识库名称
Obsidian重启持久化：PASS
Agent只读访问：PASS
同名覆盖：无
社区插件/外发：0
```

## 验证提示词

```
独立验证本章：1. 核对Obsidian来源和版本；2. 从Obsidian与文件系统分别读取安装验证.md；3. 核对绝对路径；4. 尝试在vault外创建无害测试文件，确认权限会阻止或需要授权；不要绕过；5. 检查是否误启用云同步、插件、remote或公开发布；6. 检查AGENTS.md能否让无聊天上下文的agent说清读写边界。输出证据和PASS/FAIL。
```

## 通过标准

- vault是普通本地Markdown目录。
- agent的唯一工作根目录明确。
- 无覆盖、无外发、无secret。
