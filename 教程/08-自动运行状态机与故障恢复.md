# 08 自动运行状态机与故障恢复

## 目标

把人工提示词升级为可补跑、可互斥、可恢复、可审计的运行系统。

## 状态机

| 状态 | 含义 |
| --- | --- |
| idle | 无活动任务 |
| running | 已冻结本轮输入并执行 |
| mechanical_ok | 摄取/同步完成，尚无合法结案 |
| draft_pending | 真实成果待用户审 |
| promoted | 用户确认的正式成果 |
| closed_knowledge | 稳定知识结案 |
| closed_drop | 明确放弃结案 |
| evolved | 有证据的规则升级且对照测试通过 |
| failed | 硬失败，带分类与恢复点 |

## 施工提示词

```
请为日常闭环设计并实现自动运行层。先写需求、设计和测试，不直接编码。必须实现：1. 明确调度频率、时区和目标日期；2. 单实例锁，多个agent不能重复运行；3. 开始时写run_id、目标日、输入清单hash和恢复点；4. 每个阶段幂等；5. 进程中断后resume，不从头制造副本；6. 电脑关机/agent未打开只记待补跑，不自动判系统故障；7. 下次打开检查预期日期，只补一次；8. 24小时内已有合法结案则跳过；9. 最大运行时长、有限重试和停止条件；10. 日志按网络、权限、运行时、依赖、上游、数据、规则冲突分类；11. 状态文件、AGENTS健康块、运行记录和主结案必须一致；12. 自动任务只能做已授权动作；外发和高成本综合模型仍需单独授权；13. 提供暂停、恢复、卸载和手动强制运行说明；14. 实现前备份，测试使用隔离样本。
```

## 恢复测试

```
请执行故障注入：A. Horizon一个源失败；B. GBrain刷新失败；C. 运行中途终止；D. 同时启动两个实例；E. 状态写入后成果写入前中断；F. 电脑错过计划时间后重新打开。验证：不重复、不丢输入、不假成功、能留下恢复点、状态一致。
```

## 通过标准

- 同一输入最多一个合法结案。
- 中断恢复不产生重复。
- 时间滞后与真实失败分开。
- mechanical_ok不冒充正式成功。
