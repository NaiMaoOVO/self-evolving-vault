# 第09章 质量闸门说明

> 执行器：`系统/quality_gate.py`（纯标准库 Python3，py3.9+ 兼容）。
> 教程：`教程/09-反馈自进化与质量闸门.md`。
> 设计原则：15 项检查各自独立函数（覆盖教材 14 条闸门：来源/日期拆分两项，新增⑮用户目标质量高于技术通过），每项输出 PASS/FAIL/WARN/N/A + 证据；任一 FAIL 退出码 1。

## 命令用法

```bash
# 对真实 vault 跑全部 15 项
python3 系统/quality_gate.py check

# 指定 vault
python3 系统/quality_gate.py check --vault /path/to/vault

# 隔离测试目标（不依赖 git 的项照跑；依赖 git/真实路径的项报 N/A）
python3 系统/quality_gate.py check --target /var/folders/.../qg-bad/vault

# 仅看退出码（CI 用）
python3 系统/quality_gate.py check >/dev/null 2>&1; echo $?
```

退出码：全部 PASS/WARN/N/A → 0；任一 FAIL → 1。

## 15 项检查方法（覆盖教材 14 条闸门）

| # | 闸门 | 方法 | FAIL 条件 |
| --- | --- | --- | --- |
| ① | 资源层零覆盖 | `git diff --name-status HEAD -- vault/00_资源库` | 出现 M/D/R/C/T 行（已跟踪文件被改/删）；新文件(untracked)允许；非 git 目录 N/A |
| ② | secret 扫描 | 正则 `sk-`{20+}、`api_key=`/`password=`/`token=`+长值，扫描 vault/*.md 与 系统/*.py | 命中且行内无占位符（`<>`/`YOUR_`/`占位`/`示例`/`模板`/`字段名` 等） |
| ③ | 来源存在 | 解析 `01_主题Wiki` 下知识卡 `[[wikilink]]`，按路径/短链 basename 在 vault 定位目标 | 任一 wikilink 目标文件不存在 |
| ④ | 日期有效 | 解析所有 .md frontmatter `created`/`updated`，匹配 ISO(`YYYY-MM-DD` 或含时间) | 任一非合法 ISO |
| ⑤ | 事实判断分离 | `01_主题Wiki` 知识卡正文含 `## 事实` 与 `## 判断` 分区 | 缺任一分区 |
| ⑥ | 不虚构实测/经历/引用 | 知识卡正文搜 `实测/亲测/我做过/亲自测试/亲历`，且全卡无 `[[wikilink]]` 与 URL | 命中无来源支撑的实测声明 |
| ⑦ | 不重复生产旧成果 | `03_输出库` 成果 frontmatter title 查重 | 同 title 出现 ≥2 |
| ⑧ | 每轮唯一结案 | `04_系统维护/蒸馏与结案/结案-YYYY-MM-DD-轮次N.md` 按(日,轮)分组 | 同(日,轮)出现 ≥2 个结案文件 |
| ⑨ | 抓取失败≠无新增 | 扫 `运行记录/Horizon-运行-*.md`：含"抓取失败"且"新入库 0/无新增"且宣称"成功" | 含抓取失败却掩盖成"无新增且成功" |
| ⑩ | GBrain 一致性（页面/索引/embedding 三维度） | 页面数：vault 实际 .md 数 vs `状态.md` `vault_md_count` vs `brain_pages`；索引/embedding：探测 `gbrain status`——serve(MCP) 持 PGLite 锁被拒时该两维度 N/A，附 pgrep serve 进程 + 退出码 + stderr 摘录证据（绝不 kill 进程） | `vault_md_count ≠ brain_pages` FAIL；页面数差异>2 WARN；索引/embedding 锁拒绝→N/A 留证 |
| ⑪ | 状态文件一致 | `状态机.json.state` vs `状态.md` `- 状态机:` vs `AGENTS.md` SM-HEALTH `状态机:` | 三方不一致（样本≥2 时比对） |
| ⑫ | 中间页不冒充成果 | `03_输出库` .md frontmatter `status` | status=draft |
| ⑬ | 连续低分/重复否决触发暂停 | `反馈与进化/反馈卡/` 中 status=dismissed、动作含否决/忽略/拒绝、或 满意度/评分/score/rating ≤2 的信号合计 ≥2 条，对照 `状态机.json.paused` | ≥2 否决/低分但 paused=false |
| ⑭ | 画像长期无更新触发审计 | `职业包/*.md` frontmatter `updated` 距今天数 | >30 天 → WARN（不 FAIL，触发审计而非伪升级） |
| ⑮ | 用户目标质量高于技术通过 | 结案类型=A(正式成果) 的结案文件 + `03_输出库` 成果文件：查技术通过声明（测试通过/闸门PASS等）与用户目标/用户确认证据（用户目标/用户验收/验收人等） | 仅凭技术通过而无用户目标证据→FAIL；仅缺用户目标字段→WARN 审计 |

## 与周进化的联动

- 闸门 ⑬/⑭ 与 `规则与画像/进化协议.md` 四条铁律配套：
  - ⑬ 配合铁律一（单次反馈不改全局）：重复否决触发暂停扩量，而非继续升级。
  - ⑭ 配合铁律三（无行为差异不标 evolved）：长期未更新只 WARN 审计，不强制伪升级。
- 周进化执行器 `系统/weekly_evolution.py` 的 review/apply 不在本闸门内，但其产出（候选信号表、version+1）是闸门 ⑬ 的输入。

## 测试覆盖

- T1 真实 vault 全量跑 check（预期多数 PASS/WARN/N/A、无 FAIL）；命令与输出摘录见 `施工记录/09-施工报告.md` 第四节。
- T2 mktemp 隔离迷你 vault 注入坏样本逐项报 FAIL：资源层篡改(git)、假secret(sk-TEST-)、断链wikilink、非法日期、知识卡缺事实/判断分区、无来源实测、成果同 title 重复、同日同轮双结案、draft 冒充成果、≥2否决而paused=false、技术通过冒充用户目标(check_15)；干净迷你 vault 应全 PASS。
- T3 单次反馈不污染：隔离环境写 1 条单次无数据反馈卡 → review 输出"只记录/候选"，且规则文件哈希前后不变。
- T4 真实 vault review：反馈卡目录仅 README 占位 → 输出"本周无可验证进化"。
