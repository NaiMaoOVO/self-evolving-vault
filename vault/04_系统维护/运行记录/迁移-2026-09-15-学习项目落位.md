## 三、闸门缺陷修复（系统/quality_gate.py）

### 修复 A · `probe_gbrain_cli` 误判 bug

- **旧逻辑**：`lock_markers = ("pglite", "cannot open", "already open", "lock")`，只要 status 输出含 `lock` 字样就判定「持锁不可用」。
- **实际缺陷**：`gbrain status` 正常输出中含 `Locks:` 标题（值为 `(none active)`），被误判为持锁 → CLI 被错误标为不可用 → check_10 索引维度与 check_16 永远拿不到结果。
- **修复**：改用精确错误信号（`timed out waiting for pglite lock` / `cannot open` / `database is locked` / `another instance`），并对 `locks: (none active)` 显式判定可用。

### 修复 B · `check_10` 判据错误

- **旧逻辑**：`elif vmc != bp: FAIL` —— 把「磁盘 md 数」与「脑内页数」当作应当相等，语义错误（脑含历史残留，本就不等）。且 `diff > 2` 才 WARN，实际用容差盖住了漂移。
- **修复**：
  - `vault_md_count` 必须与**磁盘实测严格一致**，否则 FAIL（计数陈旧必刷）。
  - `brain_pages` 与磁盘差额 ≤ 已知残留数（4）→ 记 PASS 并注明；超出 → WARN 提示疑似未入库新卡。

### 新增 C · `check_16_unimported_new_notes`（第 16 项）

- **目的**：直接做 brain↔disk 集合差，专捕「磁盘有、脑中无」的笔记 —— 即本次漏掉马原卡的那类静默漂移。
- **实现**：`gbrain list --limit 5000` 取全量 slug（小写归一），与 `iter_md(vault)` 相对路径集合做差；排除 README 类占位文件。
- **降级**：CLI 不可用时如实返回 `N/A` + 证据，绝不伪造结论。
- **受控验证**：放置一张未 import 的临时探针卡 → check_16 正确报 `WARN` 并点名该文件；探针已清理。

> 注：初版比对曾因两处原因误报——`gbrain list` 默认仅输出 50 行（截断），以及 brain slug 全小写而磁盘保留原大小写。均已修正（显式 `--limit`、大小写归一）。
