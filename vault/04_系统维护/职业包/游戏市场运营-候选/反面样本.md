# 反面样本

## 样本状态

**样本不足——待用户提供 3 份被否决/失败成果。**（用户无历史成果资料可采样，阶段B未满足，2026-08-22）

- 教程第05章阶段B要求"至少 3 份被修改、否决或失败的成果"；当前 0 份。
- 样本建立前：失败定义仅含 [[成果类型与完成定义]] 中的红线推导项，无法验证真实失败模式。
- 不得虚构失败样本或编造否决原因。

## 失败信息采集模板

请用户提供 **3 份被否决/被大改/失败的成果**，每份按以下模板采集：

```
- 成果类型：<方案计划|报表复盘|内容文案|分析报告>
- 日期与场景：<何时、用于什么场合>
- 否决/修改人：<谁>（可只写角色）
- 否决原话/转述：<逐字或转述，敏感信息脱敏>
- 失败原因分类（可多选）：
  - 数据准确性（来源缺失/数字错误/口径不清）
  - 时效性（过期信息/逾期交付/未标注截止时间）
  - 合规（违禁用语/概率公示/隐私/版号/未成年人）
  - 结构（目标缺失/逻辑断裂/要素不全）
  - 表达（风格不符/详略失当）
  - 判断（结论超出证据/误读竞品）
- 后续处理：<修改后被采用|放弃|换方案>
- 若修改后采用：关键改动点 <...>
- 敏感等级：公开/内部/敏感
```

## 建立后动作

1. 失败原因聚类 → 验证/修正 [[成果类型与完成定义]] 各类失败定义；
2. 与 [[黄金样本]] 差异对比 → 产出"通过/否决判据"，作为判断规则证据；
3. 合规类失败 ≥2 例 → 候选规则 R3 获得证据支撑（见 [[判断规则]]）。
