# 进化协议

> 教程第09章规定：让真实反馈改变下一轮，同时防止一次意见污染全局。
> 本文件是周进化的最高规则，违反任一铁律即判 FAIL（由 系统/quality_gate.py 与 系统/weekly_evolution.py 执行）。

## 四条铁律

1. **单次反馈不改全局**
   - 一次意见（强度=一次/low）只能：立即修事实错误或安全问题、只记录、提出进化提案。
   - 不得直接修改任何全局画像/规则/方法/模板/Skill 文件。
   - 执行点：`系统/weekly_evolution.py review` 对单次反馈只输出"只记录/候选"，不写入规则文件。

2. **≥2 重复或结果数据才升级**
   - 升级为稳定规则的门槛：同一（对象,范围）信号出现 ≥2 次，或任一反馈附结果数据（转化率/点击率/次数/%等可量化证据）。
   - 未达门槛的信号一律停留在"候选"，不升级。
   - 执行点：`weekly_evolution.py review` 的强度判定函数。

3. **无行为差异不标 evolved**
   - 规则版本号 `version+1` 后，必须用同类旧任务和新任务做前后对照，确认存在可观察的行为差异，方可将该规则标为 `evolved`。
   - 仅 version+1 而无前后对照证据的，不得在规则/画像里写"已进化/evolved"字样。
   - 执行点：`weekly_evolution.py apply` 只做 version+1 增量；标 evolved 需人工附前后对照记录。

4. **无信号写"本周无可验证进化"**
   - review 窗口内无合格反馈卡，或全部信号未达升级门槛时，周报必须明写"本周无可验证进化"，不得用模糊措辞伪进化。
   - 执行点：`weekly_evolution.py review` 无反馈卡时直接输出该结论。

## 升级流程（用户批准制）

1. `weekly_evolution.py review` 产出候选信号表 → 标注每条强度判定。
2. 对"可提稳定规则"信号，人工复制 `04_系统维护/规则与画像/模板/进化提案模板.md` 到 `04_系统维护/反馈与进化/进化提案/`，填写证据/旧规则/新规则/影响/风险/观察周期。
3. 用户审阅提案，显式批准后执行 `weekly_evolution.py apply <提案> --approved`。
4. apply 仅做：目标规则文件 `version+1`（增量）、提案 `status: open → accepted`、提案 `updated` 刷新；不触碰其他规则文件。
5. 标 evolved 需在下一轮同类任务产出后，附前后对照证据再人工补写。

## 与质量闸门的关系

- 闸门 ⑬ 连续低分或重复否决触发暂停扩量：与铁律一配套——重复否决 ≥2 触发状态机 `paused`，暂停扩量而非继续升级。
- 闸门 ⑭ 画像长期无更新触发审计：与铁律三配套——长期未更新只 WARN 触发审计，不强制伪升级。
