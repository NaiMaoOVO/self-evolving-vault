# gbrain v0.46.25.0 发布：修复关键数据完整性问题

## AI 摘要（Horizon 日报）

gbrain v0.46.25.0 作为一次大规模积压发布，合并了 62 个社区拉取请求和约 50 个维护者修复，关闭了 87 个问题。该版本重点修复了嵌入回填、同步和搜索缓存中的关键数据完整性缺陷，包括防止向量被静默破坏、修复同步删除错误页面以及解决搜索缓存跨源污染问题。所有修复均基于复现的 bug 并附带失败优先测试，每个拉取请求都经过单独试合并和测试。此外，该版本还改进了操作透明度，如 CLI 输出超过 64KiB 时确保完整传输，并增加了 Windows 平台支持。用户可通过 `gbrain upgrade` 自动升级，或手动运行 `gbrain apply-migrations --yes` 并验证 `gbrain doctor` 和 `gbrain stats`。

**「背景」** gbrain 是一个向量数据库项目，用于存储和检索嵌入向量及相关数据。在之前的版本中，嵌入回填、同步和搜索缓存等操作存在数据完整性问题，可能导致向量被静默删除、错误页面被删除或缓存数据串扰。这些问题在特定条件下（如多列嵌入、CJK 文本）尤为严重。本次发布通过引入探针门控、内容修订戳和注册表感知写入等机制，从根本解决了这些缺陷。

**「影响」** 对于 gbrain 用户，此版本修复了可能导致数据丢失或检索错误的关键缺陷，特别是嵌入回填和同步操作，建议尽快升级。对于开发者，该版本提供了更可靠的 API 和操作透明度，如 `source_id` 参数和 `--json` 输出，有助于构建更健壮的应用程序。

## 原文 excerpt

The backlog release: 62 community pull requests merged, ~50 maintainer fixes, and 87 open issues closed in one landing. Every pull request was individually trial-merged and tested before inclusion; every fix started from a reproduced bug and shipped with a failing-first test. The headline classes: embedding backfills can no longer quietly destroy vectors (probe-gated invalidation, honest counts, content-revision staleness, registry-aware writes end to end), sync can no longer delete the wrong page or be repointed by a foreign repo, search caching can no longer serve one source's rows to another or one query's rows to a different query, page timelines survive filesystem rebuilds, large piped CLI output is delivered to the last byte on every path, and the DB config plane is finally read at runtime.
Added
- Ops accept an explicit per-call source_idonget_page/delete_page/restore_page— honored or rejected, never silently ignored. Destructive ops act only within the caller's write authority; federated read grants confer no delete access.
- gbrain migrate-enginenow copies the facts table and all config rows (minus engine-local keys, printed when skipped) with a per-table copied-count summary — a migrated brain arrives whole.
- Doctor warns when chat_fallback_chainis set but inert. Contributed by @Masashi-Ono0611.
Changed
- Embedding backfills and stale sweeps are honest end to end: a live embedder probe gates any invalidation, a run that nulls vectors but embeds zero fails loudly, updated pages re-embed on content change (not just signature), and embed_skippages are never invalidated into a permanent hole.
- The embedding write path, stale selectors, coverage counts, invalidation, and bootstrap verify all resolve the same active embedding column through the registry — multi-column brains no longer see false 0% coverage or phantom stale loops.
