# AGENTS.md — vault 级规则入口（自进化知识库）

> 本文件是 vault 内所有智能体的最小规则入口。工程级总规则见上级目录 `../AGENTS.md`。

## 工作区声明

- 本 vault（`/Users/chenzixun/Documents/自进化知识库/vault`）是唯一知识库工作区。
- 五层业务目录已由第04章建立完毕（2026-08-22）：`00_资源库/`、`01_主题Wiki/`、`02_项目库/`、`03_输出库/`、`04_系统维护/`。其中 `00_资源库/外部知识/` 与 `04_系统维护/运行记录/` 由第03章按教程授权创建。新建目录须遵守下方"五层架构规则"。

## 写权限边界

- agent 可写本 vault。
- **其他 DSH 项目/会话的智能体同样可写本 vault 业务目录，库主已授权免逐次确认（2026-08-23）；红线见下节。**
- vault 之外的文件只读；`教程/` 目录一律只读，禁止修改。

## 授权红线（一律先向用户请求授权）

- 删除任何文件或目录。
- 外发：网络上传、邮件、发布。
- 批量改名。
- 移动原始资料（尤其 `vault/00_资源库/` 原始资料，禁止覆盖、移动、删除）。

## 安全边界

- 不输出 secret。
- secret 只写环境变量或被 git 忽略的本地配置。

## 追加规则

- 后续章节（GBrain、Horizon 等）的运行规则将按章追加到本文件。

## brain-first 协议（第02章追加，2026-08-22）

- 涉及用户、项目、历史决策和知识库内容的问题，先用 gbrain 检索（`gbrain search` / `gbrain query`），再回源文件核对原文。
- brain 检索结果必须附带来源文件路径（slug ↔ vault 文件）；无来源的结果视为线索而非事实。
- Obsidian 写回后，按 `施工记录/02-刷新协议.md` 执行增量刷新（import → 获授权后 embedding → 一致性检查）。

## 五层架构规则（第04章追加，2026-08-22）

五层职责（详细版见 [[01_主题Wiki/知识管理架构/知识库五层架构|知识库五层架构]]）：

| 层 | 职责 | 落位规则 |
| --- | --- | --- |
| `00_资源库/` | 原始证据 | **只读**：不覆盖、不移动、不删除、不改名；新原始资料经收件箱分拣后新建卡 |
| `01_主题Wiki/` | 稳定知识 | 只收蒸馏/验证过的知识卡；新建前先查重（vault + gbrain），重复更新既有卡 |
| `02_项目库/` | 进行中项目与决策 | 项目卡 + 决策卡；结案后按结案记录归档 |
| `03_输出库/` | 正式成果 | 只放达成本卡"完成定义"并通过验收的成品 |
| `04_系统维护/` | 入口、规则、状态、日志 | 系统自描述；状态文件 `04_系统维护/状态.md` 小节结构固定供机器解析 |

- 根目录只保留入口文件：AGENTS.md、首页.md、收件箱.md（及既有验收证据文件，清理需用户授权）。
- 目录上限：每层最多 3 个当前需要的二级目录（按需少建）。已知例外：`04_系统维护/` 含第03章遗留 `运行记录/` 共 4 个，已登记偏差待用户裁决；新增二级目录一律先确认未超上限。
- 文件名全局唯一（slug 唯一性约束，见刷新协议）。
- 八类卡模板位置：`04_系统维护/规则与画像/模板/`（原始资料卡、知识卡、项目卡、决策卡、成果卡、反馈卡、进化提案、结案记录）。新建任何卡先复制对应模板。
- 结案铁律：每轮只能结案为正式成果、稳定知识、明确放弃三者之一（见 [[04_系统维护/规则与画像/模板/结案记录模板|结案记录模板]]）。
