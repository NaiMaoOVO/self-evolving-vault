# 知识库五层架构

## 适用条件

- 本 vault 全部内容的组织与新增文件落位；亦是各章施工的目录契约。

## 事实

- 五层顶级目录与职责（来源：教程/04章施工提示词，../教程/04-知识架构与首次全量蒸馏.md）：
  - `00_资源库/`：原始证据，只读。
  - `01_主题Wiki/`：稳定知识、方法、案例、Skill。
  - `02_项目库/`：正在推进的问题、项目和决策。
  - `03_输出库/`：可实际使用的正式成果。
  - `04_系统维护/`：入口、规则、画像、状态、反馈和日志。
- 教程约束：根目录只保留 AGENTS.md、首页、收件箱等必要入口；每层最多 3 个当前需要的二级目录。（来源：同上）
- 卡片体系：原始资料卡、知识卡、项目卡、决策卡、成果卡、反馈卡、进化提案、结案记录八类模板，位于 `04_系统维护/规则与画像/模板/`。（来源：本章施工，模板文件在库可查）
- 结案铁律：每轮只能结案为正式成果、稳定知识、明确放弃三者之一。（来源：教程/04章要求7，[[04_系统维护/规则与画像/模板/结案记录模板|结案记录模板]]）

## 判断

- 【判断】五层的本质是"证据 → 知识 → 成果"的单向链路加系统自描述层：资源层只读保证证据不可污染，主题层承接蒸馏，项目层承载过程，输出层只放验收过的成品。
- 【判断】根目录极简（仅入口文件）使知识库对人和 agent 的入口唯一化，降低导航成本。

## 假设

- 【假设】三层以内二级目录足以承载长期演化——待第07-10章压力测试；超出时按进化提案流程扩层。
