# 02-刷新协议

- 编制日期：2026-08-22
- 编制者：第02章施工子智能体（第二阶段）
- 适用：vault（数据源 evolving-kb）内容变化后，使 brain 检索层与 Markdown 真相源保持一致

## 刷新契约（标准流程）

```
Obsidian 写回（人在 Obsidian 中编辑/新建/修改 md）
  → gbrain 增量 import（见下）
  →（获得用户按批授权后）gbrain embed —— 当前 embedding 禁用，此步跳过
  → 一致性检查（见下）
```

1. **增量 import**

   ```bash
   export PATH="$HOME/.bun/bin:$PATH"
   gbrain import "/Users/chenzixun/Documents/自进化知识库/vault" --no-embed
   ```

   - embedding 禁用期间**必须**带 `--no-embed`。
   - 增量语义（实测）：仅导入新增/变更文件，未变更文件 skipped。

2. **一致性检查**

   ```bash
   ls /Users/chenzixun/Documents/自进化知识库/vault/**/*.md | wc -l   # 或 find vault -name "*.*.md" | wc -l
   gbrain stats    # Pages 数应与 vault 中 md 文件数相等（当前基线：6 = 6）
   ```

   - 数不相等时的定位步骤：`gbrain list --type note` 对照 `ls vault` 逐个核对 slug ↔ 文件名。
   - 新增文件后：检索该文件的独特关键词应命中（模板见 `02-安装验收记录.md`）。

## 路径变更处理（重命名/移动文件）——实测规则

实测证据（受控探针，2026-08-22，详见验收记录）：**import 不会自动清除被改名文件的旧页面**，重命名后新旧两个 slug 并存，同一内容双命中（索引噪音+事实来源歧义）。

处理规则：

1. 重命名/移动文件后，先执行增量 import（新 slug 入库）。
2. 识别旧页面：`gbrain list --type note | grep <旧文件名>`。
3. 清除旧页面：`gbrain delete <旧slug>`（软删除，72h 内可恢复）。
   - **删除属授权红线**：清除 vault 真实笔记的 brain 页面前须用户授权；agent 自建的测试页探针除外。
4. 复验：`gbrain search <该内容独特关键词>` 只应返回一个（新）来源。

## 重复 slug

- slug 由文件名生成；同名文件（不同目录）会产生同 slug，后导入覆盖先导入（put 语义）。
- 规则：vault 内**文件名保持全局唯一**（当前根目录平铺，天然满足）；第04章建立五层目录后沿用此约束。
- 发现重复时：`gbrain history <slug>` 查看版本覆盖记录，回源文件核对后重命名文件并按"路径变更处理"执行。

## 失效页面（stale/orphan）

- 现象：`gbrain search` 命中已不存在于 vault 的内容；或 `gbrain doctor` 的 orphans 检查。
- 诊断：`gbrain list --type note` 与 vault 文件清单 diff。
- 处理：确认为已删除/改名残留 → `gbrain delete <slug>`（授权红线）；不确定时先 `gbrain get <slug>` 回源核对。

## 索引噪音处理规则

- 不该入库的内容：`.obsidian/` 配置、`.DS_Store`（import 仅收 md，已天然排除）、草稿/临时笔记。
- 规则：临时内容写在 `/var/folders/.../T/opencode`（预批准临时区），不进 vault；测试笔记用"测试-"前缀并显式声明用途与保留期限。
- 探针/测试页用毕即 `gbrain delete` 清理，并在验收记录留痕。
- 已知残留：软删除页面的 chunk 计数不立即回落（实测 chunks 6→8→8），72h 硬清除后应回落；一致性检查以 **Pages 数**为准，不以 Chunks 数为准。
